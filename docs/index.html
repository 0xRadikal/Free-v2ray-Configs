Does it actually work? — measured, not estimated

The large majority of any free config pool is dead at any moment. That is a property of free configs, not of this repository, so it is measured rather than hidden. A config reaches verified/ only if it passed every round of a real HTTP request through the proxy.

⚠️ Read this before quoting any percentage above. These numbers were measured from one host, on one day, on one link — the country is shown as “Tested from”. A config that fails from a datacentre in one country may work perfectly from another, and the reverse is just as true. So verified/ means “this config answered a real request from the machine that ran the test” — not “this config will work for you”.

A status of unknown means the source produced no result in the run that wrote health.json, so it is counted separately from ok, empty and fail rather than being folded into any of them.
In practice this is usually not a missed request: the pipeline keeps cross-run memory in state.json and deliberately skips sources it has quarantined for repeatedly returning nothing, so they are never fetched at all and therefore never get a status. A source can also show unknown simply because it was added after the last run.
